## About Me

</div>

I'm **Shreya Pathak**, a Computer Science undergraduate (B.Tech, CGPA 9.0/10) and an aspiring **Software Engineer** with a strong focus on **AI/ML** and **full-stack development**. I enjoy building systems end-to-end — from hardware-integrated IoT pipelines to ML pipelines to production-style web applications — and I approach every project with a software design mindset: modular, extensible, and built to scale beyond the prototype stage.

My project work spans **distributed systems** (IoT-to-cloud data pipelines, multi-database backends), **applied machine learning** (intrusion detection with measurable performance gains), and **full-stack engineering** (React/Node.js applications with role-based access control). I care about the details that make systems production-ready — clean architecture, structured code reviews, and designing for real-world constraints rather than just demo-day completeness.

As an open-source contributor with **GirlScript Summer of Code (GSSoC)**, I've collaborated asynchronously with maintainers across the globe, reviewed and merged pull requests, and helped improve code quality in unfamiliar, multi-contributor codebases — experience that shaped how I think about writing code other people will actually read and extend.

## Featured Projects

<details>
<summary><strong>IDentix — IoT-Based Human Recognition System</strong></summary>
<br/>

A biometric authentication system combining an ESP32 microcontroller with physiological sensors to recognize and monitor users in real time, paired with a distributed IoT-to-cloud data pipeline and a web dashboard.

| Category | Details |
|---|---|
| **Stack** | ESP32, Physiological Sensors, Firebase, Real-Time Data Pipeline, Web Dashboard |
| **Scale** | Distributed IoT-to-Firebase pipeline supporting continuous, real-time recognition and monitoring |
| **Performance** | 40% reduction in simulated authentication latency |
| **Security** | Biometric-based authentication layer built on physiological signal recognition |
| **Impact** | End-to-end documented system architecture spanning hardware integration, data flow, and UI, following structured software design principles |
| **Repository** | [View Repo](https://github.com/shreyapathak08/identix) |

IDentix was designed and deployed as a scalable proof-of-concept for biometric access control, with particular attention to how hardware signals, cloud data flow, and the user-facing dashboard fit together as one coherent system rather than disconnected components.

</details>

<details>
<summary><strong>Network Intrusion Detection System — Machine Learning</strong></summary>
<br/>

A scalable, end-to-end machine learning pipeline trained on the NSL-KDD dataset to classify network traffic into five distinct intrusion attack categories.

| Category | Details |
|---|---|
| **Stack** | Python, Scikit-learn, Pandas, NumPy, Random Forest, SMOTE, NSL-KDD Dataset |
| **Scale** | Classifies 5 network intrusion attack types across the NSL-KDD benchmark dataset |
| **Performance** | 98.8% F1-score (Random Forest); +18% minority-class recall via SMOTE oversampling |
| **Security** | Core focus: detecting and classifying network intrusion patterns for threat identification |
| **Impact** | Designed for extensibility to additional attack categories; bottlenecks debugged via feature importance and confusion-matrix analysis |
| **Repository** | [View Repo](https://github.com/shreyapathak08/nids-ml) |

This project focused as much on diagnosing *why* the model underperformed on minority classes as on the final F1-score — the SMOTE-based rebalancing and feature importance analysis were both driven by systematically inspecting the confusion matrix rather than tuning blindly.

</details>

<details>
<summary><strong>Zyngo — Full-Stack Distributed Application</strong></summary>
<br/>

A full-stack event management platform supporting real-time event publishing and registration, with role-based access for organizers and participants.

| Category | Details |
|---|---|
| **Stack** | React, Node.js, MongoDB, Firebase, Role-Based Access Control (RBAC) |
| **Scale** | Concurrent, real-time event publishing and registration across organizer and participant roles |
| **Performance** | Multi-system distributed backend designed to maintain data consistency across MongoDB and Firebase |
| **Security** | RBAC enforced at both the frontend and backend layers |
| **Impact** | Applies established software design patterns to solve a real distributed-state-consistency problem, not just a CRUD app |
| **Repository** | [View Repo](https://github.com/shreyapathak08/zyngo) |

Zyngo's core engineering challenge was keeping two different data stores (MongoDB and Firebase) consistent under concurrent writes — solved through a structured distributed backend design rather than a single source of truth.

</details>
